# ACME Salary Management

An HR application for employee records, salary updates and history, and basic pay summaries. Scope is recorded in REQUIREMENTS.md and choices in decisions.md.

## Local setup

Use Node.js 24 LTS and npm.

On this computer, a portable Node.js installation is available beside the project. In PowerShell, run the following from the project folder before using npm.

```powershell
$env:Path = (Resolve-Path '..\.tools\node-v24.22.3-win-x64').Path + ';' + $env:Path
```

```sh
npm ci
npm run dev
```

Open http://localhost:3000.

## Current stage

Login and shared navigation are implemented. Employee and Pay Summary routes currently contain headings. The relational schema and repeatable 10,000-employee seed are implemented. Connecting employee screens to the database is the next increment.
## Demo login configuration

Copy .env.example to .env.local and set DEMO_USERNAME, DEMO_PASSWORD and SESSION_SECRET. Use a random secret of at least 32 characters. Restart the development server after changing these values. A local .env.local has already been generated on the development computer. Open it locally to view or edit the demo credentials.

The session cookie is HTTP-only, uses SameSite=Lax and expires after eight hours. Production uses HTTPS-only cookies. All HR pages require a valid session. Changing the configured credentials or secret invalidates old sessions.

## Source structure

- src/app contains routes and shared page layouts.
- src/features/auth contains the login form and authentication actions.
- src/components contains reusable controls and navigation.
- src/lib/auth contains server configuration and session validation, with unit tests beside the session rules.
- src/lib/db contains the database client, schema, reference data and deterministic seed generator.
- scripts contains database setup and seed commands. Employee, salary and pay-summary feature folders will be added with their screens.

## Database setup and demo data

```sh
npm run db:setup
npm run db:seed
```

By default, these commands use an ignored local SQLite file named salary-management.db. The seed command also applies the schema if needed. Set DATABASE_URL and DATABASE_AUTH_TOKEN in .env.local for a hosted libSQL Turso database. Production requires hosted database configuration.

The seed creates exactly 10,000 synthetic employees across six departments, countries and currencies. Approximately 10% have pending salaries. It uses fixed input data and a fixed generator seed, so fresh databases receive the same records. Employees with salaries have an initial salary history entry.

Rerunning the seed preserves existing records and edits. If a database already has employees without this seed's completion marker, seeding stops and preserves them. A failed seed rolls back all employee/history inserts and can be retried. Schema setup is versioned and repeatable.

Employee IDs are generated by the database (EMP-00001 through EMP-10000 for the seed, followed by EMP-10001). IDs remain fixed. Amounts use integer minor units, with currency precision recorded in the currencies table. Salary and currency are both present or both pending. Database triggers record initial salaries and subsequent changes atomically, avoiding history entries for unchanged pay or details-only edits.

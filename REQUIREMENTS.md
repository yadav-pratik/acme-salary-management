# ACME Salary Management

## Goal

Give ACME’s HR manager a web application for maintaining base salary records for 10,000 employees across multiple countries. HR should be able to find an employee, update their pay, and answer routine compensation questions without combining spreadsheets.

## In scope

| HR workflow | Acceptance criteria |
| --- | --- |
| Find an employee | Search by name or employee ID, filter by country or department, and browse paginated results across the full 10,000-employee dataset. |
| Add and edit employees | Create employees with an employee ID, full name, department, and work country. HR can edit the name, department, and work country. The employee ID stays fixed. Enter salary and currency at creation or leave compensation pending and enter both later. Show **Salary pending** on the employee record until a salary is entered. |
| Review and update salary | View and update the employee’s annual gross base salary. Show a dated history of the first salary entry and later updates, including the previous and new amounts when applicable. Salary changes take effect immediately on save. Save the current salary and history entry together. |
| Answer pay questions | Select a currency and optionally filter by work country and department. Show the median, lowest, and highest salary and the count of employees included. Show a separate count of employees with pending salaries for the selected country and department. Show an empty state when there are no salaries to summarize. |

## Data and access

The system uses a relational database. The hosted demo uses synthetic data generated by a repeatable seed script for 10,000 employees across multiple countries, currencies, and departments. HR workflows require a demo login. Configure its credentials through server-side environment variables and keep credential values out of Git.

## Out of scope

- **Excel import and export.** The seeded dataset demonstrates the day-to-day workflow. Migration needs separate rules for column mapping, validation, and duplicate handling.
- **Payroll, taxes, bonuses, and benefits.** The first release focuses on annual gross base salary. Calculating take-home pay or total compensation requires additional data and country-specific rules.
- **Exchange-rate conversion.** The salary summary uses one currency at a time. Conversion would require decisions about rate sources and dates.
- **Scheduled changes, approvals, and employee self-service.** The first release focuses on direct updates by an HR manager and preserves a history of those updates.

## Delivery criteria

Deliver a working React or Next.js UI and backend, a relational database, and the seed script. Include fast, deterministic unit tests for salary validation and pay summaries, and verify salary updates and history together through the app. Provide a deployed demo, a short walkthrough video, and a Git repository with incremental commits, setup instructions, and notes on design decisions and how AI contributions were verified.
